# 雷达与 AIS 标定工具

独立运行的 Vue 3 + Element Plus + Fastify 调试工具。支持多雷达、多 AIS 来源匹配组、统一历史回放、逐台人工粗调安装点与北向偏差、AIS 引导关联检查、固定关联的局部 EM 自动精调、参数版本及任务证据导出。

## 启动

使用 Node **22.22.3** 与 npm；版本由 `.nvmrc` 和 `package-lock.json` 固定。

```powershell
cd F:\radar-tool
nvm use 22.22.3
npm ci
npm run dev
```

前端：[http://127.0.0.1:5173](http://127.0.0.1:5173)，Fastify：[http://127.0.0.1:3100/api/health](http://127.0.0.1:3100/api/health)。开发代理读取同一 `.env` 的 `HOST`、`PORT`，默认仅监听本机。未配置真实数据源时展示空状态；产品不提供 Mock 项目，不导入或展示已标记为合成数据的旧记录。合成数据生成器仅位于测试夹具中。

生产方式在同一个 Fastify 端口提供页面和接口：

```powershell
npm run build
npm start
```

访问 [http://127.0.0.1:3100](http://127.0.0.1:3100)。`npm test` 运行 Node 回归测试，`npm run build` 运行 Vue 类型检查和 Vite 生产构建。

## 调试流程

1. 在“设备关联”登记雷达与 AIS 来源，再建立匹配组。一个组属于一个数据源，包含 1—8 台雷达与 1—100 个 AIS 来源；同一设备可用于多个组。雷达编号对应查询的设备列，AIS 编号对应来源列。组内共享 AIS 候选集合，船舶身份由数据关联计算，不预先绑定雷达轨迹和 MMSI。
2. 在“匹配调试”选择组和完整回放时段。左侧“选择雷达”列出组内已登记设备，加载前即可选择，加载后保持为当前调整雷达；匹配组查询读取完整成员集合。可点击“框选船舶区域”，在地图按住鼠标拖出矩形，松开完成，Esc 取消。区域只筛选 AIS 位置，雷达保留原始极坐标。打开页面或切换组只恢复目录与条件；点击“加载匹配组”后由后台一次读取所选完整时段，前端显示准备进度并允许取消。全部成员成功后一起发布完整会话并传给前端。加载完成后，播放、跳转、逐帧、插值和尾迹均使用本地已加载数据。重新加载期间保留旧画面，失败或取消不发布部分数据。数据菜单的“重新读取远程数据”重新读取完整时段并建立新会话。
3. 各雷达以不同颜色叠加，两类观测共用真实毫秒时间轴。雷达按设备与轨迹、AIS 按 MMSI，在相邻两个真实位置之间按回放时间线性插值：在固定 ENU 平面连接端点，不限制两点的时间间隔。雷达先把两端原始极坐标按当前参数投影，再插值；候选、对比和具备两端历史存储坐标的图层同步移动。尾迹按所选秒数裁剪到插值位置，地图跟踪及关联线使用展示坐标。首个位置之前不显示，不向末点之后外推；AIS 继续保留最后位置，雷达没有后续点时沿用至少 5 秒的末点保留窗口。导入或结构化输入包含静态尺寸报告时，按报告时刻更新 AIS 长宽和船形，船艏向与其他上报字段按已到达报告更新；详情区分插值位置与真实上报时间。历史字段在暂停、跳转和回退时按对应时刻恢复；点击 AIS 补查的后续尺寸按下述显示覆盖规则使用。可控制成员显示、播放、暂停、跳转和倍速。左右方向键及时间轴两侧按钮会暂停并切换上一帧/下一帧；一帧为组内雷达、AIS 动态或静态报告的一个去重观测时刻，到达边界后停在完整请求范围内。空格切换播放/暂停，输入控件编辑、弹窗及抽屉内不触发全局播放快捷键。点击地图或列表中的雷达、AIS 目标后，地图保持当前缩放并居中跟踪，回放、回退和参数重算时同步更新；目标暂缺时保留最后视野，重新出现后继续跟踪；再次点击同一目标取消选择和跟踪，点击其他目标切换跟踪对象，“全域”或取消选择也可结束跟踪。覆盖条展示完整请求范围，包括首尾无数据区间。切换当前雷达保留各自调整参数和搜索设置。
4. 左侧“参数调整”保留经纬度、北向偏差与米制微调；点击“朝向”输入框获得焦点后，鼠标滚轮向上增加、向下减少 0.1°，跨越 0°/360° 时循环。也可拖动 R 安装点及 ↻ 旋转手柄。所有操作使用同一换算，暂停时也重算。对比参数可选快照参考值、保存版本、按回放时刻生效的版本。
5. 选择当前雷达并完成人工粗调，在“自动标定”设置 AIS 附近距离、位置各方向与朝向修正范围；地图蓝框由当前参数和位置修正上限派生。可独立圈选“拟合 AIS 区域”和“雷达排除区域”，前者筛选同时刻 AIS 状态，后者按冻结人工初值投影排除框内及边界雷达观测，均不改变查询区域或原始回放。点击“筛选附近雷达”后检查 AIS、雷达轨迹、训练时段有效时刻数、持续时间、距离 P50 和运动误差，逐项保留或剔除关联；地图可定位关联并切回原始雷达回放。当前参数、门限、ROI、排除区、时段、快照或当前雷达变化后须重新筛选。检查有效且选择非空时才能“创建标定任务”，立即取得编号，由后台复用当前雷达完整原始输入。初值、关联标识与全部设置随任务冻结；后续调参、切换或关闭页面不改写或取消任务。时间范围使用已加载完整时段，修改查询时间后须重新加载。任务显示实际进度，允许取消并记录失败原因，可从历史恢复查看；恢复设置或使用候选后须重新检查关联。项目、单位与时间对齐核实要求继续生效，点击补查的后续尺寸仅用于显示。
6. 右侧查看目标和候选，在“标定证据”中比较人工初值与候选使用同样样本计算的训练/验证点数、支持、背景和残差，并查看原始数量、筛选保留及排除统计、粗评分图和复现信息。点击候选行或“对比”，保留当前手调草稿，在地图上方并列显示当前与候选的经度、纬度、朝向及“候选减当前”差值，并显示固定 ENU 平面的东西、南北位移和距离；朝向差取最短有符号角差。地图自动定位两个安装点，用橙色表示当前、青色表示候选，显示各自朝向箭头、位移连线与差值标注。切换候选重新定位，手调时差值同步更新；“结束对比”保留草稿，“使用候选”才将候选参数和原任务设置载入草稿，随后可保存版本。精调不自动采用参数；验证下降或未稳定优于人工时保留人工参数，只有证据满足条件的自动候选能设为工具回放生效版本。
7. “查询与标定历史”区分完整会话、旧分窗条件、旧历史和已归档，支持加载更多。打开旧分窗条件时，按原成员、时段和区域完整读取全组，生成完整会话，原目录保留。完整查询和归档按原方式打开；已释放的临时数据按固定历史条件回源。手动保存参数、导出当前雷达和“完整归档到指定目录”均复用已加载完整输入；归档将完整数据、可取得的原文和任务证据保存在用户指定的服务器目录。任务只剩摘要时明确显示其范围；参数目录不保存全部观测。连接地址和认证信息不会从项目配置进入导出。

保存候选默认没有生效时间。设置生效时间仅改变本工具历史回放的版本选择，不调用生产参数发布接口。相同生效时间的版本按最新保存版本选择。

界面固定在视口内，参数区、目标表格和抽屉独立滚动；小屏目标列表通过抽屉打开。地理底图采用 Leaflet 1.9.4 和 OpenStreetMap。底图不可访问时可关闭“地理底图”，目标、ENU 网格、圈选及手动操作仍可使用。拟合不依赖底图或地图视野。地图按每类最多 2,000 个当前目标、12,000 个尾迹采样点显示，雷达显示配额在可见成员间分配；目标表格局部滚动。这些展示限制不裁剪任务快照。

普通回放一次接收完整时段的业务数据，时间轴覆盖完整选择范围；拖动时预览目标时间，松开后在本地跳转。尾迹为 0—300 秒，两类观测的前后真实报告均来自已加载完整输入。当前完整工作集保存在服务端内存，更换、释放或重启后可按历史条件回源或读取归档。旧分窗目录及服务端窗口接口用于已有记录和调用方兼容；窗口接口仍使用有限缓存与明确的覆盖声明。

地图 16 级起，具备有效尺寸和已知定位参考点偏移的 AIS 按上报米数 1:1 绘制“尖船艏、矩形船身、平直船艉”轮廓。船长为 A+B，船宽为 C+D；船体以回放定位点为锚点，使用当前展示位置及 A/B/C/D 偏移。显示朝向优先使用真船艏向，缺失时使用有效 COG（0°≤COG<360°）表示运动方向。远景、尺寸或参考点偏移不齐时，按该显示朝向绘制三角形；两种方向均缺失或不可用时显示无方向定位圆点。船艏向和 COG 的真实 0° 均有效，朝北显示。详情保留原经纬度、船长、船宽、四边距离及独立的船艏向和 COG 字段。A=C=0 表示仅有总尺寸、未提供参考点偏移，使用定位符号。四边距离定义见 [IMO AIS 安装指南第 5.2—5.3 节](https://www.navcen.uscg.gov/sites/default/files/pdf/marcomms/imo/Circulars/IMO.SN.Circ.227_AIS_Installation.pdf)。显示朝向回退不改写原始字段，也不进入标定模型。

原始 AIS 项目中，点击地图或列表中的 AIS 船舶会固定点击瞬间的回放时间 T，按该船当前来源和 MMSI，只读查询 ClickHouse 的 `[T, T + 48 小时)`，取第一份有效静态尺寸。T 对应当时的显示位置，插值位置和保持显示的末点均使用点击时的回放时间。返回后立即更新 A/B/C/D、长宽和地图，详情显示真实报文日期、来源和类型。点击尺寸作为同一会话的显示覆盖，在播放、回退和切换当前雷达时持续使用；新一次有效结果替换该船旧覆盖。结果不改写历史快照、原始位置、船艏向或标定输入，不写 SQLite、不保留补查原文；更换会话或快照时清空。无有效尺寸或查询失败时保留已有尺寸并显示原因。再次点击同一目标仍取消选择，重新选中时按新的点击基准时刻查询。

## 设备登记与关联

`config/projects.json` 定义数据源连接引用、库表/列映射、时间和单位契约。服务首次读取某个项目时，将其雷达与 AIS 清单初始化到本地 `data/radar-tool.sqlite`，同时生成默认匹配组。此后该项目的设备和关联以 SQLite 登记为准，通过前端编辑；重启不会用模板覆盖用户修改。连接、字段、单位或解析器设置仍在服务端配置中维护。

登记雷达可编辑名称、参考经纬度和参考朝向，已有设备/站点信息保留；AIS 登记填写名称和来源编号。已登记编号不可直接更改，应先登记新编号，再修改组成员。仍被组引用的设备不能删除；删除组不删除历史会话、快照、任务或参数版本。编辑仅保存本地配置，不验证设备在线状态，不读取或改动生产登记表。新参考参数只用于后续查询，历史快照保留查询时配置。

匹配组每次编辑增加修订号；加载请求携带修订号，过期配置被明确拒绝。会话固定组成员、修订、查询时段、AIS 查询区域和每台雷达的快照 ID/摘要，恢复历史时一并恢复区域，配置后续修改不改写历史。一个组内所有雷达共用所选 AIS 来源；不同雷达需要不同 AIS 集合时，可建立多个组。

## 真实数据接入

1. 直接读取原始 AIS 时复制 `config/projects.raw.example.json` 为 `config/projects.json`；通过已有结构化 HTTP 接口接入时使用 `config/projects.example.json`。复制 `.env.example` 为 `.env`，设置 `PROJECT_CONFIG` 和连接变量。项目配置只保存环境变量名；实际凭据留在部署环境。两个本机文件已加入 `.gitignore`。
2. 核实库表和列名、设备列类型、原始距离/角度的缩放与方向。配置只接受受控标识符，筛选值通过官方 ClickHouse 客户端参数绑定。
3. AIS 可选择已有后端的结构化 HTTP 入口，或读取原始报文并复用现有后端同族的 [DMA AisLib](https://github.com/dma-ais/AisLib) 解析库。工具不另写 AIS 协议解码器、不采集设备，也不直接猜测 `wp_position` 的来源与完整性。
4. “数据详情”中的只读检查返回 ClickHouse 版本、时区、雷达列名/类型以及引擎、分区键、排序键和主键。检查不读取生产参数，也不自动确认时间、单位或 AIS 覆盖。
5. 在真实样本核实后，将项目 `verified`、`unitsVerified`、`alignmentVerified` 均设为 `true`，并按实际时间含义设置 `timeSemantics` 为 `event-time` 或 `receive-time`，才能自动拟合。未确认的项目仍可查询预览。修改配置后重启服务，再点击“加载匹配组”建立新回放；历史会话和快照保留创建时的核实状态，重新打开旧记录不会应用新的声明。

`rangeScaleToM` 表示源距离乘数；标准方位为：

```text
azimuthDeg = normalize(sourceAzimuth × azimuthScaleToDeg × azimuthSign + azimuthZeroDeg)
真北方位 = azimuthDeg + bearingOffsetDeg
```

标准方位从北顺时针。已施加到源值的偏差需要在映射中明确处理，不能再次叠加。AIS 结构化字段使用最终业务单位，不重复执行旧后端的 0.1 缩放。

远程历史查询采用 `[start, end)`，完整时段跨度不设上限；工具最多同时执行一个远程只读查询或结构检查，完整历史数据准备也使用独立的单任务槽。雷达逐台串行查询；原始 AIS 模式的完整动态报告在组内共用，船体尺寸由用户点击时单独补查；结构化 HTTP 模式按雷达分别调用，保留 `radarId` 上下文。每条 ClickHouse 请求设置 `readonly=1`，资源与返回数量限制由远程数据库及账号配置管理。ClickHouse 连接采用当前客户端默认网络超时。任何一路失败即停止，不发布半份组数据，不自动扩大范围或重试库端错误。不自动轮询生产库，打开页面不自动读取大正文或访问生产库。

可选 `queryArea` 为 WGS84 矩形 `{west, east, south, north}`，包含边界，不支持跨越 ±180° 经线的矩形。原始 AIS 历史查询要求配置 `ais.columns.messageType`，SQL 仅选择消息 1/2/3/18；相邻位置、分窗和远程逐帧时刻使用同一类型范围。框选还要求 `ais.columns.lng/lat` 映射到已核实的经纬度列；当前列为 Float32，SQL 使用参数绑定的闭区间，解析后按真实位置再次筛选。历史加载仅取得动态观测，尺寸由点击单独补查。雷达不按历史存储经纬度裁剪，以免安装参数偏差使有效极坐标观测被丢弃。实际扫描量仍受远程表的分区和排序键影响。

远程数据库返回资源限制错误时，工具区分扫描行数、执行时间、读取量、内存或并发原因。扫描行数包含稀疏索引块内未命中的行，不等于返回的 AIS 报文或目标点数量；短时段也可能触及远程数据库自身的限制。

查询时间参数类型必须与实际列一致。当前现场列为 `DateTime`，配置 `timeType: "DateTime"`，绑定 UTC 秒时间；在已连接的 ClickHouse 22.6 中，错误使用 `DateTime64` 参数会影响索引裁剪。秒精度边界向上取整，保持原半开范围的成员关系；声明 `DateTime64` 的其他数据源保留毫秒参数。时间/设备值使用参数绑定，不格式化时间列进行筛选。

文件导入最多 120,000 条业务观测、32 MB，条数校验只在上传入口执行。真实查询通过业务范围和解析完整性校验后，创建当前内存工作集，只将结构化目录写入 SQLite；完整数据由显式归档保留。

### 点击获取后续静态尺寸

`POST /api/projects/:id/ais/dimensions` 仅支持已配置 MMSI 和消息类型列的原始 AIS 项目，请求来源须属于该项目。`positionTime` 是点击基准时刻，必须包含时区：

```json
{ "mmsi": "258315000", "aisSourceIds": ["202606002"], "positionTime": "2026-11-10T01:40:00.000Z" }
```

服务端按来源、MMSI 和消息 5、19、24 查询 `[positionTime, positionTime + 48 小时)`，包含左端点、排除右端点。接收时间正序每批读取 20 条候选，交给 DMA 库解析，跳过 24A 和无效尺寸，返回按报告时间找到的第一份有效 5、19 或 24B 尺寸。先查起点之后一小时，没有有效尺寸时继续后续 2、4、8 小时等不重叠窗口，累计最多 48 小时。20 条为批大小，不是查找总上限；页边界的同刻报告完整读取，跨页及跨窗口分片仅在本次范围内衔接，越界才能补齐的报文按缺片报错。

该范围与历史加载时段、位置框选及服务器当前日期独立；请求发出后播放继续前进也不改变范围。全部请求只读，共用工具查询槽。耗时仍受远程扫描限制、索引及 MMSI 历史分布影响。

成功响应只包含精简尺寸；`queriedAt` 记录实际请求时间，`positionTime` 记录查询起点：

```json
{
  "projectId": "radar-202607",
  "mmsi": "258315000",
  "positionTime": "2026-11-10T01:40:00.000Z",
  "queriedAt": "2026-11-11T02:00:00.000Z",
  "report": {
    "mmsi": "258315000", "sourceId": "202606002", "messageType": "24",
    "eventTime": "2026-11-10T01:45:30.000Z",
    "dimensions": { "bow": 40, "stern": 10, "port": 4, "starboard": 5 },
    "lengthM": 50, "widthM": 9, "parserVersion": "dma-aislib-2.8.8-bridge-v4"
  }
}
```

查完无有效尺寸返回 HTTP 200、`report: null`；参数或点击时间无效返回 400，缺片或远程资源限制返回 422，上游越界或解析失败返回 502，缺少配置返回 503。多片消息依赖完整原文及可正确定位的 MMSI/消息类型元数据。接口不补船艏向；等比例船形使用有效真船艏向或回退到有效 COG，并要求已知定位参考点及合适缩放级别。

配置的服务端 URL 接受 `POST application/json`，可通过环境变量传入完整的 `Authorization` 头值。URL 本身不接受账号、口令和查询参数。

```json
{
  "schemaVersion": 1,
  "radarId": "202601001",
  "sourceIds": ["receiver-a"],

  "end": "2026-11-10T02:10:00.000Z"

```

响应：

```json
{
  "schemaVersion": 1,
  "complete": true,
  "parserVersion": "existing-backend-v1",
  "parseStats": { "failedReports": 0, "pendingFragments": 0 },
  "warnings": [],
  "observations": [],
  "staticObservations": []
}
```

`observations` 的每条记录遵守下述 AIS 动态契约；可选 `staticObservations` 遵守 `aisStatic` 契约，供回放独立更新尺寸。所有记录均需处于请求的时间和来源范围内。动态空数组仅表示在已完整查询且正确解析的范围内无有效动态观测。`complete` 必须为 true，解析版本必须等于项目配置；解析失败数必须为零。未组包数量显式保存在证据与覆盖提示中。失败分片、静默解析异常及分页截断必须由已有后端返回失败，不能伪装成完整空结果。

框选时请求额外携带可选 `queryArea: {west, east, south, north}`。已有接口可据此收窄位置查询，并保留需要的静态信息；工具在接收结构化观测后也按此范围筛选位置，保持两种 AIS 入口的区域语义一致。

已有后端负责按来源隔离多片报文上下文、跨查询分片衔接，按 MMSI 和有效时段关联静态信息。所有记录必须位于请求时间范围和来源集合内。工具校验这些条件，不实现第二套协议解析器。

旧分窗接口的请求还携带 `playbackRange: {start, end}` 和 `includeNeighbors: true`。该模式下，已有后端需返回窗口主体、相关目标在完整 `playbackRange` 内的前后相邻报告与历史静态初值，并声明 `neighborsComplete: true`；记录可超出当前窗口，但必须处于完整范围及选定来源内。缺少覆盖声明返回 503，避免将缺上下文误显示为目标消失。当前通用结构化 HTTP 适配未提供缓存外逐帧时刻查询，该操作明确返回 503；完整查询接口仍按原契约可用。

## JSON 业务契约

可导入完整快照的导出文件，也可直接导入一个数据对象。必需顶层字段：

| 字段 | 含义 |
| --- | --- |
| `schemaVersion`、`name`、`projectId`、`radarId` | 版本固定为 1；项目 ID 使用字母、数字、下划线或连字符；一份快照只包含一个雷达。 |
| `reference` | 固定 ENU 原点 `{lng, lat}`，WGS84。搜索候选不会更换参考点。 |
| `baseline` | 查询时参考对比参数 `{lng, lat, bearingOffsetDeg}`；与精调任务冻结的当前人工初值分别保存。 |
| `timeRange` | 推荐显式提供 `{start, end}`，半开范围，所有时间均含 Z 或时区偏移。缺省时只能推导已导入观测跨度，并显示限制。 |
| `timeSemantics` | `event-time`、`receive-time` 或 `unverified`。 |
| `unitsVerified`、`alignmentVerified` | 数据提供方核实单位、时间及小窗口对齐规则后的声明，不由工具自动推断。 |
| `radar`、`ais` | 原始业务观测数组，数值保持数值，缺失使用 null/省略。 |
| `aisStatic` | 可选的 AIS 静态尺寸观测数组，缺省为空；与动态位置分别保存。 |
| `provenance`、`warnings` | 版本/来源/查询证据与已知覆盖限制，不放凭据。 |

观测记录均包含 `id`、带时区的 `eventTime`、可选 `receiveTime`、`mappingVersion`、`raw` 和 `quality` 数组。`raw` 存放源值、序号与其他需要追溯的信息。服务端生成 `timeMs`，保留毫秒，不在服务层格式化展示时间。

雷达另包含 `sourceId`、`deviceId`、`trackId`、`rangeM`、`azimuthDeg`、可选 `storedPosition`。`deviceId` 必须等于顶层 `radarId`，ID 在雷达数组内唯一。`storedPosition` 仅用于历史基线核对，标定不反推原始极坐标。

AIS 另包含 `sourceIds`、9 位 `mmsi`、`messageType`、`position`，可选 `sogKnots`、`cogDeg`、`headingDeg`、`accuracyM`、`dimensions`。`accuracyM` 是已量化的米制不确定性，不是协议中的 accuracy 位。COG 沿用参考项目，保留解析库协议值乘 `0.1` 后的结果，包含 360 及超过 360 的数值；已有结构化接口直接提供业务单位。零经纬度、零速度和 0° 船艏向有效；511 船艏向、102.3 SOG 作为不可用值保留质量标记，转换为 null。

`aisStatic` 每条记录还包含 `sourceIds`、9 位 `mmsi`、`messageType` 和必需的有效 `dimensions`，尺寸来源须属于该报告的来源集合。静态报告没有位置，不生成轨迹点或增加动态观测数。导入、旧快照及结构化 HTTP 输入中的这些报告，回放按截至当前时刻已收到且有效的尺寸更新；缺少 `aisStatic` 时按空数组处理。原始 ClickHouse 新查询的 `aisStatic` 为空，点击后续尺寸使用独立显示覆盖。导入的 120,000 条上限包含雷达、AIS 动态及静态观测。

船体尺寸使用：

```json
{
  "bow": 60,
  "stern": 20,
  "port": 8,
  "starboard": 8,
  "observedAt": "2026-11-10T01:00:00.000Z",
  "validFrom": "2026-11-10T01:00:00.000Z",
  "validTo": "2026-11-11T01:00:00.000Z",
  "sourceId": "existing-static-source"
}
```

同一 MMSI、时刻、消息类型、位置、运动、精度和关联静态信息均相同的多站报告合并；原始报告及各接收时间保存在 `raw.reports`，来源、原始 ID 集合保留。同一时间不同消息类型保留；冲突位置保留证据，并从自动对齐中排除该船该时刻。

## 自动标定实现

共享 `shared/geo.js` 使用 WGS84→ECEF→固定 ENU 和显式东/北公式，供手动、回放、拟合使用：

```text
East  = East0  + r × sin(θ + β)
North = North0 + r × cos(θ + β)
```

当前模型是矩形船体内均匀分布与各向同性高斯误差的卷积，通过两个方向的高斯 CDF 差计算归一化密度。误差方差叠加测距、随距离增加的测角、AIS 精度和时间误差；这是保守的各向同性近似，不是已验证的真实散射分布。

尺寸必须已观测且在有效期内。缺真船艏向时不使用 COG：有尺寸时退化为有界尺度的各向同性高斯（船体项上限 80 m，质量先验 0.6），无尺寸时使用配置的退化尺度（默认 24 m，先验 0.4）。背景在覆盖所有安装候选可达位置的固定有限区域内均匀分布，混合权重归一化；同船可承接多个雷达观测。精调背景支持域由实际局部位置边界与雷达业务契约的 100000 m 距离上限预先确定，不从验证段或已筛掉的观测估计；该上限不是设备真实覆盖。旧 `refinement: null` 保留按原始观测最大距离确定研究区域的行为。

工作台采用 `options.refinement`：冻结当前人工初值，在采样前通过 `shared/refinement.js` 筛选稳定关联，人工确认后固定每个雷达观测对应的船舶。默认设置如下，均为可调工程初值：

| 设置 | 默认值 | 允许范围 |
| --- | --- | --- |
| AIS 附近距离 `maxDistanceM` | 200 m | 10—2000 m；当时已知且有效的尺寸提供船体外包圆余量 |
| 位置各方向修正 `maxPositionShiftM` | ±100 m | 1—2000 m |
| 朝向修正 `maxBearingShiftDeg` | ±5° | 0.1—30°，周期角 |
| 稳定关联 `minTrackPoints` / `minTrackDurationMs` | 4 个真实时刻 / 12000 ms | 2—100 / 1000—300000 ms |
| 运动容许尺度 `motionToleranceM` | 75 m | 1—1000 m |
| 雷达排除矩形 / 人工关联标识 | 无 / 未检查 | 检查后必须保留非空关联集合 |

候选只使用训练段真实 AIS 状态；训练 AIS 索引截止 `splitTime` 之前。连续片段须同时满足时刻数、持续时间与相对位移一致性，距离失配、相对位移突变或超过 `max(minTrackDurationMs, 2 × maxGapMs)` 的断报会分段，单次靠近不纳入整条轨迹。同轨迹多船候选保留竞争信息；训练重叠点按冻结初值下最近距离归属，数值等距（差不超过 `1e-6` m）排除并计数，人工单选可明确归属。一船可承接多条雷达轨迹，同一观测只采样一次。验证只延用训练末尾连续片段确定的船舶身份，不按验证距离或分数换船；断报或门限失配后停止续接。

筛选后按雷达轨迹均衡分配并在时间上均匀抽取，再按轨迹和时间桶加权。局部位置范围为冻结初值在固定 ENU 中的东西、南北坐标各加减修正上限，朝向只搜索初值加减角度上限；人工初值本身参与候选比较。默认空间粗步长 65 m、角度粗步长 5°、拟合/验证采样上限 240/120、候选数 6、每起点 EM 上限 16 轮。50,000 上限约束位置与角度组合的粗网格候选数，不是原始雷达观测数。位置与角度评分、EM 精化及人工初值指标采用同样样本和同一概率模型，候选变化不重新引入船舶或观测。

旧接口省略 `refinement` 或显式设为 `null` 时继续采用旧算法与历史设置摘要：在 `bounds` 中全角度搜索，再进行多起点 EM；原有短轨迹降权、采样和概率关联保持兼容。工作台恢复旧任务设置后进入当前精调流程，须重新检查关联。

按完整数据时段的最后 30% 保留验证数据；精调关联及稳定性只由训练段确定，验证分数不参与候选排名或 M 步。结果 `initialMetrics.training/validation` 与候选使用完全相同的样本和模型；验证分数或支持下降、训练和验证未显示稳定改进时标为证据不足，不宣称优于人工、不自动应用。若修改设置后，新验证区间与本工具此前完成任务的数据区间重叠，结果标为“复用时段 / 证据不足”，须另取未参与调参的时段复核。同一设置的复算不增加新的独立证据。外部调参历史无法由工具自动识别。

单船、低支持、验证表现下降、短轨迹占主导、近平行运动、边界最优或竞争峰等情况明确降低结果状态。包络残差统计只针对后验概率 ≥55% 的关联点，同时展示整批观测的支持与背景比例；退化模型的残差以 AIS 参考点为基准。粗网格热力图与精化步长均不是统计置信区间。

标定和关联评分的时间对齐采用已声明核实窗口内的最近真实报告，默认 ±2 秒；不插值、不按速度外推，时间差通过模型误差体现。无速度时使用 5 m/s 的保守时间误差尺度。超出对齐窗口的匹配状态保持缺失。前端插值只生成独立的展示坐标，不覆盖真实位置、极坐标、观测时间或原始字段，不参与拟合、残差或快照导出；关联线连接当前展示位置，评分仍对应真实观测。回放从已加载完整数据中寻找相邻端点，回退按对应时间重算。自动拟合仅使用相对固定参考点的 ENU 水平距离不超过 30 km 的 AIS 位置观测，超出部分逐点过滤并在任务证据中记录数量；同一船舶的范围内观测继续参与拟合。过滤不改写原始快照和回放数据；过滤后没有可用 AIS 时明确报错。

标定任务创建时保存固定条件并引用完整输入的 `snapshotId` 与 `snapshotHash`。兼容的分窗提交先预留快照 ID，完整准备成功后才发布快照及摘要；该准备阶段通过任务接口查询进度和取消。任务失败、取消或服务重启中断时，条件和状态保留。

版本保存请求包括 `snapshotId`、`name`、`parameters`、`effectiveFrom`（null 表示候选）、`source`（manual/task）。自动候选还需 `taskId`、`candidateIndex`；服务器取任务里的参数，不信任客户端伪造的候选值。保存响应的完整任务证据包含冻结设置及 `initialMetrics`；版本列表仅返回目录摘要，完整初值证据通过关联任务详情或导出读取。

会话、快照、任务和版本列表默认每页 50 条，使用 `cursor` 和响应头 `X-Next-Cursor` 继续读取；保留数组响应，支持相应项目、雷达、组或状态筛选。列表只读目录，不加载正文或计算完整数据哈希。查询和读取默认返回 `schemaVersion: 2` 回放投影，按字段编码并共享相同 AIS。完整快照的 `?format=full` 可取得兼容对象；窗口投影明确声明部分覆盖，不能作为完整证据导入或拟合。窗口原始详情在原接口携带 `?playbackId=…`，窗口淘汰后返回 410。窗口请求自身支持断连及显式取消；完整准备型 POST 加 `?async=1` 返回 202，再通过准备接口取得结果，当前只允许一个完整准备任务。

本地使用 Node 22 内置 SQLite 和 WAL，路径为 `data/radar-tool.sqlite`，可用 `DATA_DIR` 调整。设备、成员、查询条件、参数、候选和结果摘要按列及关联表保存。精调初值、门限和排除区保存在 `task_refinements`，人工选择按行保存在 `task_refinement_associations`；初值指标复用 `task_metrics/task_metric_groups` 的 `rank = -1`，候选从 0 开始。既有历史尺寸表保留，新历史加载与点击补查均不读写该表，新增记录不写 JSON 正文或对象 BLOB。旧分窗描述、固定成员和实际读取指纹保存在 `window_playbacks/window_playback_radars/window_playback_sources/window_playback_reads`；窗口观测和原文只留在有限内存缓存。显式完整准备的数据保存在当前工作集，更换、释放或重启后需要回源或读取归档。目录事务全部成功后才替换可用输入；运行中的拟合独立保留输入直到结束。任务的热力图等完整证据只在当前内存或可用历史/归档中保留，结构化摘要明确标记其范围。

首次升级逐条校验旧 `records/settings` 或 JSON 文件，只建立目录与关联，保留 ID、SHA-256 和原文，不复制全部轨迹。旧表停止写入，旧文件保持原样；失败记录不提交，修复后可从已提交游标继续。旧正文和 WAL 未自动清理，也未强制压缩数据库。显式归档保存 gzip JSON 文件，SQLite 仅登记位置、大小和摘要；归档与旧快照读取均校验完整性。表、缓存、迁移和测量说明见[历史查询与存储文档](docs/HISTORY_QUERY_PERFORMANCE_PLAN.md)。

备份前停止服务，再复制数据库及需要保留的归档文件。仍只支持单个 Fastify 进程和一个拟合工作线程；服务重启后未完成任务标记“已中断”。生产历史继续只读查询远程 ClickHouse。

主要实现：`server/registry.js` 本地设备/匹配组，`server/sources.js` 完整查询与静态初值，`server/window-sources.js` 窗口与定向上下文，`server/window-playbacks.js` 分窗描述/缓存/完整准备，`server/clickhouse.js` 只读连接与单并发，`server/ais-parser.js` 本地库调用，`shared/refinement.js` 共用筛选与稳定关联，`server/fitter.js` 局部精调与旧模式搜索，`shared/model.js` 固定关联采样/船体密度/评估，`shared/session.js` 组回放选择和 AIS 展示合并，`client/useWorkbench.ts` 时间轴、关联检查和逐雷达状态，`client/shipGeometry.ts` 船形与定位点偏移。

回放验收通过真实 Fastify 接口及 Node 中运行的 Vue 工作台状态，覆盖完整时段加载、加载前雷达选择、失败或取消保留旧画面、本地播放与跳转、旧分窗历史的完整恢复、参数草稿与点击尺寸覆盖，以及后台标定对完整输入的复用和生命周期。精调测试以筛选/拟合公共结果、Fastify 任务与重启恢复、Vue 工作台状态为边界，覆盖稳定/竞争关联、人工剔除、训练验证隔离、检查失效与迟到结果保护、真实 worker 计算、初值对照、导出及版本证据，保留原始观测和回放。旧服务端窗口接口继续保留缓存、取消、相邻报告和 AIS 分片的兼容验证。现场 ClickHouse 的旧分窗测量结果见[历史查询与存储文档](docs/HISTORY_QUERY_PERFORMANCE_PLAN.md#6-验证结果与验收范围)。类型检查、生产构建和源码/接口测试不等于浏览器或真实雷达精度验收。本项目按工作规则不进行浏览器调试；地图渲染、拖动交互、真实完整查询性能和独立时段标定仍需实际环境验收。多起点有限网格与 EM 不构成唯一全局最优证明，不输出统计置信区间，不拟合时间偏移、距离比例或每船形变。
