### 2.2 通用 ClickHouse 执行

`ChUtil` 通过 `ClickHouseDataSource(AppPro.chUrl)` 创建连接；`getSqlList(sql)` 使用 `createStatement().executeQuery(sql)`，再经 `AisUtil2.convertList` 转为行映射。
现有调用把筛选值拼进 SQL 字符串；独立工具应在查询适配边界使用参数绑定，不照搬字符串拼接。源码连接配置仅作为来源定位，不作为工具配置示例。

### 2.3 `RadarUtil.getPositionMap` 路径

`fromType == "0"` 时查询 `radar_data_combine_all`，选出 `date、lng、lat、speed、trackId、direction、distance`。
时间条件为可选的 `date >= startTime` 和 `date <= endTime`，`areaCode` 取方法参数；结果按日期排序，可分页。
结果以 `trackId` 分组，并将它同时写进 `Radarposition.id` 和 `mmsi`。这里的雷达 `mmsi` 是兼容旧模型的轨迹标识，不是船舶 AIS MMSI。
**筛选差异**：该 SQL 的列表筛选实际写成 `mmsi IN (...)`，不是 `trackId IN (...)`；不能据此认定能正确按雷达轨迹筛选。新工具应按已核实的真实轨迹列筛选。

其他 `fromType` 值进入 AIS 分支，查询 `stationtest_datagram` 的 `date、message、stationMmsi`，并以 `lng != 0`、时间范围及可选 `mmsi` 列表筛选。
当前 AIS 站点筛选写死为 `202512009、202601002、202601003`；这些是数据源标识，不应成为新工具的固定范围。
每行复用 `RadarReceiver.messageUtil.dealSingleRawData → Message → Radarposition`，位置、速度等来自报文解析，不能把 `message` 直接当成已结构化坐标。
此路径还有两项限制：第 100 行从外层结果 `map` 读取 `stationMmsi`，没有从当前行读取；位置检查只接受北纬、东经范围。后续适配不得照抄这两处行为。

### 2.4 历史接口路径及信息损失

`POST /api/radarposition/getHistoryList → getSingleShipTrack → getShipTrack → dealTrackList` 是另一条查询链路。

| 分支 | 实际查询 | 对标定的限制 |
| --- | --- | --- |
| 雷达 | `radar_data_combine_all`；取格式化到秒的 `date、lng、lat、speed、trackId AS mmsi、areaCode` | 没取 `distance、direction`；固定筛 `areaCode = 202601001 / 202601002`，方法参数未用于此条件。 |
| AIS | `stationtest_datagram`；取 `date、message`，筛选上述三个固定 AIS 站点 | SELECT 未带 `stationMmsi`，回调却读取它，来源信息缺失；位置、COG、SOG 仍依赖报文解析。 |
| 汇总 | 仅保留 `date、lng、lat、course、speed、mmsi`，按标识分组，按 `date` 去重 | 丢失雷达原始极坐标、设备来源及其他字段；同一秒多点可能被合并，不能作为拟合数据契约。 |

AIS 分支把解析后的 `cog、sog` 乘以 `0.1`；这说明当前代码有该缩放，不代表所有结构化表也要再缩放一次。
旧 `matchTrack` 只在完全相同的时间键中找 200 米内最近点，然后把所有命中过的对侧标识用逗号连接。
它没有估计安装点或朝向，也没有处理船体扩展、杂波和多解，不能复用为本工具的自动标定结论。

### 2.5 已有结构化 AIS 路径

`AisUtil2.getHistoryList` 查询 `wp_position` 的 `speed、date、heading、code、lng、turn、lat、course、accuracy`，按单个 MMSI 和开区间时间筛选。
其下层方法虽然名叫 `getHbaseList`，实际使用本对象的 ClickHouse 连接执行查询；这里不是 HBase 访问。
`ChUtil.insertToPosition` 存在向 `default.wp_position` 写入 11 个位置字段的代码，`insertChmodel` 中也有调用。
这些读写代码表明“已有结构化历史可供复用”是可调查的路径，**没有证明当前部署持续写入、表完整、或能覆盖所选项目**。

`Chposition` 当前模型没有 `stationMmsi`，也没有 A/B/C/D 尺寸；不要把 `code` 擅自解释为采集站点。
当前融合历史查询没有使用这条结构化路径。启用直接读表前，应确认 MMSI、时间、经纬度、单位、来源与静态船信息关联能力；无法按站点区分时必须说明限制。
优先由已有后端输出统一结构化结果，复用其解析器并保留来源；直接读表是满足契约后的接入方式，不是绕过核实的捷径。

## 3. 字段、单位与时间约定

### 3.1 字段来源

| 工具业务字段 | 现有来源 | 使用约束 |
| --- | --- | --- |
| 雷达设备 | `areaCode` | 纳入轨迹键；不同雷达的相同 `trackId` 不能合并。 |
| 雷达轨迹 | `trackId`，旧模型有时放入 `mmsi` | 与真正的 AIS MMSI 分开保存；轨迹重置/复用规则待确认。 |
| 雷达时间 | 查询用 `date`；采集代码另有 `utc、time` | 接收时间、设备时间和目标时间不能混用。 |
| 雷达距离/方位 | `distance、direction` | 在查询适配边界映射为米和度；保留原值及转换元数据。 |
| 雷达已有坐标 | `lng、lat` | 用于基线显示和核对，不能替代极坐标，也不能反推为无损原始值。 |
| AIS 身份/来源 | `mmsi` / 报文中的 MMSI；`stationMmsi` | 一船可被多站接收；保留来源集合和去重依据。 |
| AIS 动态位置 | 当前由 `message` 解析；结构化候选为 `wp_position` | 核实定位时间、接收时间及有效值；缺失值不能默认为零。 |
| AIS 航向/速度 | `Message.cog、sog、trueHeading`；候选表 `course、speed、heading` | COG 是对地航向，真船艏向决定船体朝向，不能无条件互换。 |
| AIS 船体/质量 | `Message.dimBow、dimStern、dimPort、dimStarboard、posAcc` | 尺寸通常需静态信息；默认字符串 `"0"` 不证明实际尺寸为零。 |

### 3.2 当前雷达采集代码能证明什么

`AppConfig.kt` 对所示报文分支的 `date` 默认使用服务器当前时间；报文中的 `utc` 经 Unix 秒整数转换，目标字段另存入 `time`。
该分支把距离乘以 `0.01`、方位乘以 `0.0001`；`Util.calculateLatAndLng` 在换算时按米、度使用它们。
`Radardata` 构造会调用该换算函数，函数包含固定安装点和 `174°` 偏差；它不是可直接作为工具配置的项目真值。
上述代码不能证明 ClickHouse 历史数据全部经此分支写入，也未核实目标 `time` 的协议单位、方位零点或历史预处理。

### 3.3 工具统一契约

内部时间使用带明确时区的真实时间点，内部距离使用米、角度使用统一约定；展示层再格式化，不在服务层把时间先截到秒。
每条观测保留 `sourceId、deviceId、trackId/MMSI、eventTime、receiveTime（若有）、原始字段、单位映射版本、质量标记`。
当前 JSON 字段为雷达 `sourceId、deviceId、trackId` 与 AIS `sourceIds、mmsi`；完整字段见 README。数据显式保存半开 `timeRange`，覆盖条和回放保留请求范围内的首尾缺报；未声明范围的导入只推导观测跨度并显示限制。
AIS 动态观测另保留经纬度、SOG、COG、真船艏向及各字段有效性；静态尺寸报告独立保存在 `aisStatic`，保留 MMSI、A/B/C/D、来源、观测时间、有效时段和原始报文。原始 AIS 的 COG 沿用参考项目 `Radarposition` 构造函数的规则：解析库协议值乘 `0.1` 后直接保留，包含 360 及超过 360 的数值；已有结构化 COG 使用业务单位。
缺失、协议不可用码和真实零值必须区分；纬度 0°、经度 0°、速度 0 都可能有业务意义，不能用通用 `!= 0` 替代有效性判断。
查询、去重、拟合与回放使用同一时间语义。前端按同一雷达设备与轨迹、同一 MMSI 的相邻真实端点，在固定 ENU 坐标中按时间线性插值，仅生成独立展示坐标；原始位置和观测时间保留。两点间隔不限制，端点范围之外不外推。AIS 在末点之后保留最后位置，雷达没有后续端点时沿用末点保留窗口。同来源静态尺寸到达时立即更新该船当前长宽与船形，无需等待新的位置报告；船艏向按已到达的动态报告更新。尺寸更新保留原始位置与位置时间；回退时恢复对应时刻已收到且仍有效的尺寸，不回填更早动态观测。标定沿用动态观测及其当时关联的尺寸，在已验证的小间隔和可接受运动条件下进行时间对齐，超出对齐窗口的候选保持缺失。

## 4. 当前查询与适配约束

当前接入雷达 `202607001 / 202607002`，AIS 来源为 `202606002`；以下模板对应已核对的表和列。时间列均为 `DateTime`，使用相同类型的 UTC 参数，避免现场旧版服务器中 `DateTime64` 参数比较影响索引裁剪。其他项目必须先核对实际类型，再选择配置中的 `timeType`。
工具统一采用半开区间 `[start, end)`，与现有大多数查询的 `<= endTime` 及 `wp_position` 查询的两侧严格不等不同。
连续时间分片因此可以衔接而不重复边界点，但多片报文解析需另处理分片上下文，不能只靠时间切片保证完整。

接入环境可先执行以下只读检查；`wp_position` 仅在确认表存在后检查，分区和排序键再用对应表的 `SHOW CREATE TABLE` 核对。

```sql
SELECT currentDatabase() AS database_name, version() AS clickhouse_version,
       timezone() AS timezone_name;
DESCRIBE TABLE radar_data_combine_all;
DESCRIBE TABLE stationtest_datagram;
DESCRIBE TABLE wp_position;
```

### 4.1 雷达极坐标历史

```sql
SELECT
    `date` AS query_time,
    areaCode AS radar_id,
    trackId AS radar_track_id,
    distance AS source_range,
    direction AS source_azimuth,
    lng AS stored_lng, lat AS stored_lat, speed AS source_speed
FROM radar_data_combine_all
WHERE areaCode = {radar_id:String}
  AND `date` >= {start:DateTime('UTC')}
  AND `date` <  {end:DateTime('UTC')}
ORDER BY `date`, trackId;
```

历史查询不预先绑定某个 MMSI 与雷达轨迹。加载后，工作台按人工粗调参数生成 AIS/雷达轨迹候选，由人工检查和保留，再固定为局部精调输入。
若只是查看指定雷达轨迹，核实字段后增加 `trackId IN {track_ids:Array(String)}`，不要照搬旧 SQL 的 `mmsi` 筛选。
如需设备时间、目标时间、序号、强度或质量字段，只能在确认列存在和语义后扩展 SELECT；不能根据模型类推定表中必有该列。

### 4.2 已有 AIS 原始报文查询

```sql
SELECT receiveTime AS source_time, stationMmsi AS ais_source_id, mmsi, message
FROM stationtest_shipborne_repeater_datagram
PREWHERE receiveTime >= {start:DateTime('UTC')}
     AND receiveTime <  {end:DateTime('UTC')}
WHERE stationMmsi IN {ais_sources:Array(String)}
  AND toString(messageId) IN ('1', '2', '3', '18')
ORDER BY receiveTime, stationMmsi;
```

当前 `source_time` 使用 `receiveTime` 接收时间，保留 `date` 为另一来源时间；不得用设备报文时间取代查询时间，也不宣称两路延迟已核实。AIS 站点列表为 `202606002`，雷达设备编号与 AIS 来源编号独立配置。
这仍然是原始报文数据，查询后通过本地 Java 适配复用 DMA AisLib 2.8.8 的 `AisPacketParser / AisMessage`，输出结构化结果；独立工具不新增协议解码器。依赖、运行方式与解析统计见 README。
普通历史查询、分窗主体及相邻位置仅选择消息 1/2/3/18，消息类型列映射为必需配置。框选增加参数绑定的经纬度闭区间：`lng >= {west:Float64} AND lng <= {east:Float64} AND lat >= {south:Float64} AND lat <= {north:Float64}`，要求配置 `ais.columns.lng/lat`；当前列已核实为 Float32。解析后按真实位置再次筛选，包含边界，合法零经度仍可查询。
普通时段查询只解析动态轨迹，不加载静态尺寸、不回溯、不从 SQLite 或前一窗口注入尺寸。新原始 AIS 标定输入没有船体尺寸，按现有缺尺寸模型退化。尺寸由点击单独取得，仅用于显示，不作为历史时刻已知尺寸的证据。边界见[点击尺寸与历史输入](HISTORY_QUERY_PERFORMANCE_PLAN.md#44-点击尺寸与历史输入)。

分窗回放还取得相关目标在完整所选时段内的前后有效位置，同刻冲突、重复报告和多来源身份保留。元数据指向不可用位置时继续定向寻找有效报告，真实 0° 船艏向有效。主窗口、相邻位置和远程逐帧查询统一限制为 1/2/3/18，不跳到被排除的报文时刻；连续窗口只复用动态上下文，冷跳转不恢复静态尺寸。

原始 AIS 项目中，点击船舶调用 `POST /api/projects/:id/ais/dimensions`，提交当前来源、MMSI 和点击瞬间的回放时间 `positionTime`，查询 `[positionTime, positionTime + 48 小时)`，返回第一份有效 5、19 或 24B 尺寸。结果立即更新显示，保留真实日期、来源和类型；覆盖在同一会话播放、回退及切换当前雷达时保留，新有效结果替换该船旧覆盖，更换会话清空。结果不进入历史快照、SQLite 或标定输入。契约见 [README](../README.md#点击获取后续静态尺寸)。
已有解析器有多片报文上下文，且上游 `dealSingleRawData` 存在静默 catch；本工具适配显式统计有效输出、未组包、被放弃片段和解析失败，解析失败不保存部分快照。来源取当前数据库行，而非外层分组 map。
每次解析按来源隔离上下文，解析失败明确报错。点击补查从起点后一小时开始，正序每批 20 条，无有效尺寸时继续后续 2、4、8 小时等不重叠窗口，累计最多 48 小时。同刻边界完整读取，跨页、跨窗片段只在本次范围内组包；缺片、放弃片段或解析错误明确返回，查完无尺寸返回空结果。动态与尺寸查询共用只读查询槽，串行访问生产库。

### 4.3 结构化 AIS 候选查询

```sql
SELECT `date` AS source_time, mmsi, lng, lat,
       speed, course, heading, accuracy, code
FROM wp_position
WHERE `date` >= {start:DateTime('UTC')}
  AND `date` <  {end:DateTime('UTC')}
ORDER BY `date`, mmsi;
```

该模板仅覆盖源码已出现的位置字段，没有编造 `stationMmsi` 或船体尺寸列。实际数据库名由连接配置确认。
表若无采集站字段，不能承诺按 `ais_sources` 筛选；需由已核实的来源映射、现有后端输出或其他满足契约的结构化源补足。
使用结构化表不再对已换算的速度/航向重复缩放；静态尺寸和真船艏向的完整性另行检查。

### 4.4 查询适配与可复现性

ClickHouse 官方支持 `{name:Type}` 查询参数，HTTP 传参使用 `param_name`；参见[官方语法文档](https://clickhouse.com/docs/reference/syntax#defining-and-using-query-parameters)。
本工具的官方 JavaScript 客户端参数绑定已在现场 ClickHouse 22.6 的短查询中验证；上游旧 JDBC 调用未改动。秒精度源使用向上取整的时间边界，保持精确半开区间的成员关系，不对时间列做格式化后筛选。
不同项目的库表/列映射由受控配置选择，值使用参数绑定；不允许把界面输入直接拼成标识符或任意 SQL。
真实查询总时段不设上限，每次只运行一个远程只读查询批次或结构检查，完整历史加载另有单准备任务槽；组内雷达逐台串行读取。分窗原始 AIS 主体与上下文共享给各雷达，连同必要历史尺寸复用；结构化 HTTP 模式保留 `radarId` 上下文，按雷达分别调用，并要求上游声明相邻报告覆盖，具体契约见 README。每条 ClickHouse 请求设置 `readonly=1`，资源与返回数量限制由远程数据库的服务端及账号配置管理；工具读取窗口完整主体与定向上下文，连接采用当前客户端默认网络超时。查询失败不发布半份组窗口，不自动扩查或重试库端错误；只有窗口缓存预算的 413 由前端缩窗重试。打开页面和切换组只恢复目录与条件，普通加载按播放位置获取观测。窗口内原始数据查询没有自动分页；本地目录采用稳定游标分页。
扫描行数包含稀疏索引块中未命中的行，与最终返回数量不同；多个数据片段的最小读取开销可使极短窗口触及远程数据库自身的限制。错误分别说明数据库返回的扫描行数、执行时间、字节、内存和并发原因。
完整组查询固定成员修订、名称、参考参数、数据契约、完整时间范围、AIS 查询区域及单位/时间声明；全部成员成功后发布完整会话与各雷达快照。前端持有完整业务数组，本地计算播放、插值、逐帧和尾迹。标定任务引用单雷达原始完整输入并独立持有到任务结束，显示转换和点击尺寸覆盖不改写输入。旧分窗描述与接口保留兼容，前端打开旧记录时按原条件完整准备全组并生成完整会话。
查询或解析失败应明确返回错误；不得默默省略失败分片后仍宣称处理了完整时段。任务数据用于复现，不成为新的通用历史入库服务。

### 5.2 回放与参数预览

1. 选择匹配组和完整时间段；需要筛区域时点击“框选船舶区域”，按住拖框、松开完成，Esc 取消。打开页面只恢复目录和条件，点击加载后通过异步准备接口一次读取完整时段。全部成员成功后统一发布，前端显示准备阶段并允许取消；失败或取消保留原画面。加载后进度条、播放、逐帧、插值和尾迹在本地完成。“重新读取远程数据”读取完整范围并建立新会话；旧分窗历史按固定条件完整恢复，原目录保留。完整归档保存到用户指定的服务器目录。没有数据时显示参考站点，不提供 Mock 数据。
2. 地图按雷达分色叠加 AIS、雷达、安装点和尾迹，可控制成员显示；全部目标共用一条真实时间轴，支持播放、暂停、跳转和倍速，不能各自按数组索引推进。左右方向键及时间轴按钮暂停并跳到组内雷达、AIS 动态或静态观测的相邻去重时刻，首尾停在请求范围边界；空格切换播放/暂停，编辑输入控件、弹窗及抽屉内保留原有键盘行为。雷达先按参数投影前后极坐标端点，AIS 使用前后报告位置，在固定 ENU 平面按时间线性插值，两点间隔不限制；尾迹按所选秒数裁剪并连接到当前展示位置，关联线使用当前两类展示端点，评分仍使用真实观测。首个点之前不显示，末点之后不外推；AIS 持续保留末点，雷达按原保留窗口隐藏过期末点。目标详情标明插值位置，时间和原始距离、方位仍为真实报告字段。端点索引随当前加载的匹配组快照重建，跳转和回退时重算。不同雷达相同的轨迹编号保留独立身份。点击地图或列表中的目标自动保持地图中心跟踪，不改变缩放；雷达优先跟随候选坐标，候选图层关闭时依次使用已显示的对比、历史存储展示坐标，AIS 跟随回放定位点。回退与参数重算同步更新中心，目标缺失时保留视野，重现后继续跟踪；再次点击同一目标取消选择和跟踪，点击其他目标切换跟踪对象，“全域”或取消选择也可结束跟踪，圈选和参数拖动期间暂缓居中。
3. 选择当前雷达，修改其安装经纬度或北向偏差后，立即从原始 `r、θ` 重算当前可见点和尾迹；暂停状态也刷新。切换雷达保留各自参数和搜索设置。
4. 提供拖动安装点、旋转朝向、东/西/南/北米制微调及数值输入；“朝向”输入框获得焦点后，滚轮向上增加、向下减少 0.1°，按 0°—360° 循环。这些操作更新同一候选参数，不能形成多套换算公式。
5. 既有对比坐标图层可选择快照参考值、保存版本或按回放时刻生效的版本。自动任务候选另提供安装参数对比：点击候选行或“对比”，以当前手调草稿为参照，不替换草稿或任务设置。地图上方并列显示当前与候选的经纬度、朝向及“候选减当前”差值；经纬度保留七位小数，朝向保留三位小数，朝向差取 `[-180°, 180°)` 的最短有符号角差，位移使用同一固定 ENU 平面的东、北分量及距离。地图取消目标跟踪并定位两个安装点，橙色表示当前、青色表示候选，叠加各自朝向箭头、位移连线和距离/角差标注；安装点重合时仍保留两个圆环与标签。切换候选重新定位，手调草稿时同步更新差值但不反复居中。“结束对比”仅清除对比，“使用候选”才载入候选参数与原任务设置。对比仅用于当前雷达与任务相同的完整输入；切换雷达或更换输入后清除。AIS 和原始雷达观测不被修改。
6. 保存候选为参数版本，记录适用雷达、生效时间、坐标与角度约定、创建来源及任务证据；手动保存参数复用当前雷达完整输入，自动候选关联原任务完整输入。历史回放可明确选择版本，窗口切换不重置参数草稿。

页面固定在视口内，参数、表格和抽屉局部滚动。主表单保留组、时段和当前雷达的常用参数；高级算法设置、质量详情、证据和历史记录通过抽屉查看。

AIS 船形在地图 16 级起按上报长宽 1:1 显示，轮廓为尖艏、矩形船身和平直船艉。A/B 为定位参考点至船艏/船艉的距离，C/D 为至左舷/右舷的距离，长=A+B、宽=C+D；图形锚定当前展示位置，定位参考点单独标出。显示朝向优先真船艏向，缺失时用有效 COG（0°≤COG<360°）表示运动方向；真实 0° 有效。远景、尺寸缺失或 A=C=0（参考点偏移未知）时按显示朝向绘制三角形；船艏向与 COG 都不可用时显示无方向定位圆点。COG 和真船艏向保持独立原值，显示回退不参与标定；标定仍使用第 6 节的模型。四边距离定义见 [IMO AIS 安装指南第 5.2—5.3 节](https://www.navcen.uscg.gov/sites/default/files/pdf/marcomms/imo/Circulars/IMO.SN.Circ.227_AIS_Installation.pdf)。

原始观测与展示坐标分离。`r、θ` 及来源字段不可被拖动结果覆盖；已有 `stored_lng/lat` 只作基线核对。
南澳设备配置中的经纬度和朝向仅作参考初值，不作为可信真值；其中的扫描距离、扫描范围不代表真实覆盖，不用于目标裁剪或拟合约束。
任务结果持久化不自动改动生产采集系统；如后续接入生产参数应用，应单独定义已有系统支持的发布接口和生效规则。

### 5.3 自动任务入口

一个任务只估计一个雷达的安装参数，可使用多个 AIS 接收源；同船同一次报告的多站重复数据先去重，保留来源集合。
去重不能仅按 MMSI 丢弃同一时刻的不同消息类型；冲突位置、不同精度和不同接收时间需要可追溯的规则。
工作台先完成人工粗调，再设置 AIS 附近距离、位置和朝向修正上限；蓝框表示由当前人工初值和位置上限派生的实际局部范围。“拟合 AIS 区域”筛选同时刻 AIS 状态；“雷达排除区域”按冻结初值投影排除框内及边界观测；查询栏的“框选船舶区域”决定远程 AIS 查询范围。三个区域独立，后两种精调筛选不改写查询条件、原始观测或回放。区域通过按住拖动、松开完成选择，Esc 取消，雷达排除区可清除。

点击“筛选附近雷达”冻结当前人工初值及设置，显示训练段候选的 AIS、轨迹、不同真实时刻数、持续时间、距离 P50 和运动误差。候选默认全选，人工可逐项剔除，并在地图查看实际保留观测与 AIS 的关联或切回原始雷达回放。检查后的有效数量来自共享筛选结果，不累加有重叠的候选摘要。人工参数、ROI、排除区、门限、局部范围、查询时段、快照或当前雷达变化使检查失效；改回原值、切回原雷达也须重新检查，过期异步结果不覆盖新草稿。恢复历史任务设置或使用候选后同样须重新检查。

完整回放通过 `{snapshotId, options}` 提交后台任务。当前工作台携带 `options.refinement.initial` 和人工保留的非空 `associationIds`；未经检查或空选择返回 400。服务器立即保存冻结输入并返回编号，使用完整原始快照计算。旧分窗调用方仍可通过 `{playbackId, radarId, options}` 提交，由后台准备完整时段后计算；省略 `refinement` 或显式设为 `null` 的旧任务继续使用旧算法。前端跟踪任务进度，关闭页面或释放回放不取消计算；后续调参不改写任务。任务可取消并保留失败原因，服务重启将未完成任务标记中断。精调不自动应用候选，参数保存及版本生效采用与手动模式相同的语义。

## 6. 自动拟合方法与当前实现边界

当前工作台采用：**人工粗调 → AIS 引导稳定关联筛选 → 人工检查 → 固定关联的局部位置/朝向搜索与多起点 EM**。船体和背景概率模型沿用原实现，人工初值与候选使用同样样本和模型比较。筛选与局部范围的完整字段契约见[精调规格](../.scratch/ais-guided-calibration/spec.md)。
旧任务及 `refinement: null` 接口保留在 `bounds` 内的全角度搜索和原概率关联算法；这条兼容路径不要求当前工作台的关联检查。

### 6.1 三个待估参数与统一换算

固定局部参考点，将 WGS84 AIS 位置和候选安装位置转换为以米为单位的局部 East/North 坐标。
参考点不能随候选移动；可用经过验证的 WGS84 地理坐标→ECEF→ENU 实现，参见 [PROJ 官方 topocentric 文档](https://proj.org/en/stable/operations/conversions/topocentric.html)。
范围较大时应评估局部平面误差，使用经验证的测地换算；不得把经纬度差直接当米，也不能为每个候选偷偷更换参考系。

待估参数为 `φ = (East0, North0, β)`：前两项是雷达安装点，`β` 是观测方位到真北方位的修正角。
统一令方位从北开始、顺时针为正；源定义不同的，在适配边界转换并保留映射。

```text
q = (r × sin(θ), r × cos(θ))
East  = East0  + r × sin(θ + β)
North = North0 + r × cos(θ + β)
```

`r` 用米，公式中的角度进入三角函数前转为弧度；`β` 按周期角处理。精调只搜索冻结初值 `β ± maxBearingShiftDeg`，跨 0° 保持连续；旧模式搜索覆盖 `[0°, 360°)`。
拟合、手动预览、结果导出和回放必须使用这组显式东/北公式，避免通用旋转矩阵的符号约定不一致。
不同时拟合比例、每船平移或任意形变；否则可能用额外自由度掩盖错误安装参数。

### 6.2 时间对齐和船体观测模型

以雷达观测时刻组织对应的 AIS 状态，使用源时间语义和已核实的小间隔对齐规则；报文间隔长、转弯或断报时降低可信度或不参与，不任意插值。
AIS 定位点是船上位置报告参考点，不是固定的船体几何中心。A/B/C/D 表示参考点到船艏、船艉、左舷、右舷的距离，参见 [ITU-R M.1371 规范](https://www.itu.int/rec/R-REC-M.1371)。
有有效尺寸和真船艏向时，在船体坐标中构造纵向 `[-B, A]`、右舷为正的横向 `[-C, D]` 外包络，再按真船艏向放到局部平面。
标定模型使用真实船艏向，不能将显示层的 COG 回退当作船艏向输入；低速、横流、倒航等情况下，COG 与船体朝向可能不同。静态尺寸须关联到观测时段。
有可用尺寸但缺真船艏向时，对朝向保留显式不确定性或不使用方向性包络；尺寸也缺失时采用有界、较低权重的退化模型，显示降级原因。
缺失字段、旧模型默认零及协议不可用码不作为真实零尺寸；容差不能任意放大到所有安装候选都能命中。

船体包络叠加雷达测距/测角、AIS 位置和已量化的时间误差；远距离的角度误差应反映为相应横向不确定性。
船内落点或接近船体边缘可以是合理观测，目标不是让每个雷达点贴住 AIS 参考点。
当前采用测距、距离乘测角误差、AIS 和时间误差的方差和，构造保守的各向同性高斯；船体矩形与该密度卷积。缺船艏向/尺寸时使用归一化且尺度有界的退化高斯，并降低船舶先验。时间采用已核实窗口内的最近实际报告，不插值或外推；具体参数、质量权重与局部范围限制见 README。

### 6.3 含背景的概率关联

同一船可以产生多个雷达点、多个轨迹片段；允许这些点同时属于同一 AIS 船舶。未关联目标可以是无 AIS 船，不直接标为鸟或杂波。
在每个时刻为有效 AIS 船舶构造归一化的空间密度 `f_j(x,t)`，并保留背景密度 `b(x)` 和背景先验 `π0`。
一种可实现的起点是“船体区域内的归一化分布，与有界参数的高斯测量误差卷积”：

```text
f_j(x,t) = (1 / area(H_j)) × ∫[u ∈ H_j(t)] N(x-u; 0, Σ_ij) du
p_i(φ)   = (East0 + r_i sin(θ_i+β), North0 + r_i cos(θ_i+β))
L_i(φ)   = π0 b(p_i) + Σ[j ∈ J(t_i)] πj f_j(p_i,t_i)
```

`H_j` 是有效船体包络，`Σ_ij` 含该观测对应的测量与时间不确定性；退化包络应改用明确定义且归一化的替代分布，不能除以零面积。
背景使用固定有限研究区域上的均匀密度，覆盖位置边界内所有候选的可能观测位置。精调以实际局部位置边界和雷达业务契约的 100000 m 距离上限预先确定该区域；该上限不是设备真实覆盖，也不从验证段或被筛掉的观测估计背景。候选、初值、训练和验证使用同一背景支持域，验证数据不能通过研究区域改变训练模型或排名。旧 `refinement: null` 沿用原始观测最大距离确定研究区域的行为。
每个观测的有效船舶集合为 `J(t_i)`，混合权重满足 `π0 + Σπj = 1`；不同数量的有效船舶下仍需归一化。精调中每点使用已检查并冻结的一艘船及背景，候选变化不重新引入其他船舶或观测；旧模式按当时有效 AIS 候选构造集合。
上述是工具的建模起点，不声称船体回波在区域内必然均匀；后续可依据实测调整散射分布，但必须保持归一化和独立验证。
仅使用 `exp(-距离²/阈值)` 而忽略区域大小、协方差归一化和背景项，不能直接当作可比较的概率密度。

E 步计算每点属于各船及背景的后验概率，例如 `γij = πj f_j / L_i`、`γi0 = π0 b / L_i`，每点的各归属概率总和为 1。
M 步固定这些概率，在位置边界和周期角约束下数值优化三个参数，使加权期望对数似然改善；精调始终遵守相对人工初值的位置和朝向上限。
扩展船体、背景项和可能随角度变化的测量误差需要共同进入目标；不能直接套用普通点对点 SVD 的闭式解。
原版 CPD 的点集模型也不能未经修改就覆盖本场景；本工具借鉴其概率配准与 EM 思路，使用矩形均匀分布与高斯卷积的扩展模型。该模型通过合成数据和密度归一化测试，真实散射分布及现场性能仍需验证。

原始点层面不采用一对一匈牙利分配，也不把一船多个点先平均后强迫贴到 AIS 点。
精调在优化前通过真实时刻数、连续片段和相对运动检查固定关联；轨迹分裂、重置或交叉时分段核查，不能假设 `trackId` 永远可靠。

### 6.4 AIS 引导筛选与局部优化

`shared/refinement.js` 的 `selectRefinementObservations(dataset, options)` 同时供前端检查和后台拟合使用，返回 `associations`、未采样的 `training/validation`、`exclusions` 和毫秒 `splitTime`。每行固定为 `{observation, ship, associationId}`；关联标识为 `JSON.stringify([deviceId, trackId, mmsi])`，不使用 UI 行号。

| 精调字段 | 默认值 | 允许范围与语义 |
| --- | --- | --- |
| `initial` | 当前人工粗调参数 | 冻结的经纬度与北向偏差 |
| `maxDistanceM` | 200 m | 10—2000 m，AIS 定位点附近距离；当时有效已知尺寸提供船体外包圆余量 |
| `maxPositionShiftM` | 100 m | 1—2000 m，固定 ENU 中相对初值东西、南北各方向的修正上限 |
| `maxBearingShiftDeg` | 5° | 0.1—30°，相对初值的周期角修正上限 |
| `minTrackPoints` | 4 | 2—100，不同真实雷达时刻数 |
| `minTrackDurationMs` | 12000 ms | 1000—300000 ms，连续稳定片段最短时长 |
| `motionToleranceM` | 75 m | 1—1000 m，相对位移一致性容许尺度 |
| `radarExclusion` | null | 按冻结初值投影的 ENU 矩形，包含边界 |
| `associationIds` | null | null 表示未检查；提交任务时须非空，未知标识明确报错 |

1. **固定输入与分段**：核对时间/单位，完成多站去重，保留缺失和质量信息；按完整时段的最后 `validationFraction`（默认 30%）划出验证段。训练 AIS 索引只包含 `splitTime` 之前的报告，不能借验证段建立训练关联。
2. **附近与区域筛选**：先按冻结初值排除雷达框内及边界点，再使用固定参考点 30 km 内、符合已核实时间窗口且无同刻位置冲突的真实 AIS 状态；拟合 ROI 按同时刻 AIS 状态过滤。标定位置不插值或外推；后续点击尺寸只用于显示，不提供筛选余量或模型输入。
3. **连续与运动检查**：按设备、雷达轨迹和 MMSI 组织候选。连续片段同时满足真实时刻数、持续时间与运动门限；缺少对齐状态、不再靠近、相对位移突变或断报超过 `max(minTrackDurationMs, 2 × maxGapMs)` 时分段。运动误差取相对偏移散布 RMS 与整段线性漂移长度的较大值，单次靠近或持续运动不一致不能保留整条轨迹。
4. **竞争与人工选择**：一船可对应多条雷达轨迹，同轨迹多个合格船舶保留竞争摘要供人工取舍。训练重叠点按冻结初值下最近距离决定归属，距离差不超过 `1e-6` m 的等距点排除并计数，人工单选可明确归属。同一雷达观测只保留一次，人工选择之外的点记录为人工剔除。
5. **验证身份冻结**：验证只延用训练末尾连续合格片段的关联；多个关联的优先级由训练段距离中位数确定，不按验证段近远或分数重新选船。训练尾段中断、验证断报、距离失配或位移突变后不续接，验证表现不影响训练候选或稳定门限。
6. **筛选后均衡采样**：仅对已检查的固定行按雷达轨迹和时间均衡取样与加权，训练权重不借用验证数量或持续时间。默认训练/验证上限 240/120；原始观测、筛选保留、未采样及各类排除数量分别保存，未关联不等于物理噪声。
7. **局部搜索与 EM**：位置范围为初值固定 ENU 坐标各方向加减位置上限，朝向为初值加减角度上限。人工初值参与比较，默认空间/角度粗步长 65 m/5°、保留候选 6 个、每起点 EM 上限 16 轮。50,000 限制仅针对位置和角度组合的粗网格候选数，不限制原始雷达观测数。粗评分、EM、初值和候选指标共用样本与概率模型，不因候选变化重选观测或扩大误差。
8. **同样本比较与输出**：`initialMetrics.training/validation` 与每个候选使用完全相同的样本和模型；候选按训练分数排名，验证不参与优化。验证分数或支持下降、两段未稳定改善时标记证据不足，保留人工参数；支持不足、边界或竞争峰继续保留原因，不自动应用候选。

搜索步长、保留候选数、采样量和停止阈值需要依据数据量、搜索区大小与实测结果配置，当前没有可承诺的时长或精度。
EM 和有限网格均可能落入局部解；多起点与粗到细搜索降低该风险，但不构成唯一全局最优证明。

### 6.5 噪声与错误关联约束

只有二维 `r、θ` 时，不能可靠分类鸟、飞行物和船舶；可选的强度、质量、速度稳定性或高度信息可用于有依据的降权，原始观测仍须保留。
背景分量承接无 AIS 船、杂波和其他未解释观测；应展示背景比例及其时段分布，不能把它们全部当作坏数据删除。
轨迹过短、AIS 位置冲突、静态信息过期和大段断报应降低支持或排除该段，排除规则及数量必须可见。
精调默认要求至少 4 个真实时刻、持续 12 秒且运动误差不超过 75 m 的连续片段，在均衡采样前排除不合格观测；旧模式保留短轨迹降权规则，采样中短轨迹占多数时不推荐参数。同时间冲突 AIS 不参与关联，过期尺寸退化，超出已核实时间窗口的状态保持缺失。原始观测和处理统计保留；竞争与无法区分数量单独展示，不把这些重叠口径直接相加当作总排除量。
若只剩一船、几乎同向平行航迹、空间范围太窄或静止目标占主导，安装平移与朝向可能难以区分；应保留多解和不确定区间。
时间偏移不是默认第四个自由参数；只有确认时间链路存在偏差，且能给出有界搜索范围时才作为扩展，并检查其与沿航向安装平移的混淆。

## 7. 结果评估、解释与保存

| 输出 | 要回答的问题 |
| --- | --- |
| 安装参数 | 候选经纬度、East0/North0、北向偏差、角度约定、搜索边界；是否停在边界。 |
| 支持量 | 有效船舶数、雷达轨迹数、时间覆盖、有效点数、关联概率、背景比例；不能只给少量成功命中的点数。 |
| 残差分布 | 到船体包络的距离及概率残差分位数，按船、距离、方向和时段分组；AIS 点距离作为辅助显示，不作为唯一目标。 |
| 候选可分性 | 候选分数差、安装位置/角度评分热力图或剖面；精化网格步长不能冒充统计置信区间。 |
| 时段验证与初值对照 | 人工初值和候选在同样训练/验证样本上的支持、背景和残差；验证仅延用训练关联，验证时段不能反复调参后仍叫独立验证。 |
| 可复现信息 | 配置/参数版本、数据快照摘要、查询解析版本、采样规则、搜索及优化设置、失败和排除统计。 |

不能只比较最近若干匹配点的 RMSE；少数点的低误差、过大船体外扩、不断提高背景占比均可能产生伪好结果。
候选比较应使用同一数据、固定研究区域和相同模型约束，同时检查支持覆盖、残差分布、跨时间一致性及独立时段表现。
当前候选只按拟合分数排序，保留时段不参与优化。修改设置后若验证区间与本工具此前完成任务的数据区间重叠，结果标记“复用验证 / 证据不足”，要求更换未参与调参的时段；工具不能识别外部调参历史。
每个候选使用同一批雷达观测；不能随地图视野或候选变换裁掉难匹配的点，也不能在评分中任意扩大船体范围。
可在分时段/分船重采样中观察参数稳定性；若输出置信区间，须说明计算方法和假设，不能直接把优化器收敛当作精度保证。
保存结果时附带“建议采用 / 证据不足 / 存在多个候选”等明确状态；证据不足时允许只保存候选，不发布生效参数。精调冻结设置按列保存在 `task_refinements`，人工关联按行保存在 `task_refinement_associations`；初值训练/验证指标与分组复用 `task_metrics/task_metric_groups` 的 `rank = -1`，自动候选从 0 开始。任务详情和导出在重启后可读取这些结构化证据；任务版本的完整证据包括 `initialMetrics`，版本列表仅为摘要，完整证据由关联任务详情或导出读取。热力图等完整过程证据仍遵守内存与显式归档的保留范围。

## 8. 真实接入和验收时的待确认事项

- **真实数据结构**：当前雷达表和船载转发 AIS 表的列、类型、秒级精度、时区及分区/排序键已只读核对；空值覆盖、保留周期和其他项目映射继续按小样本核实。
- **雷达原始性**：`distance、direction` 是否保留采集值、是否已缩放/加偏差；零点、顺逆时针、量程、轨迹 ID 复用及多点/多轨迹语义。
- **时间链路**：`date、utc、time` 与 AIS 时间分别代表什么，设备/服务器时钟同步情况；目标 `time` 的协议单位尚未核实。
- **结构化 AIS**：`wp_position` 是否持续写入，所选时段和设备是否覆盖，`code` 含义、来源是否可追溯，是否可以按采集站筛选。
- **AIS 完整性**：多片报文和跨分页解析能否复用；静态尺寸、真船艏向、不可用码、动态/静态关联有效期及多源冲突规则。
- **查询可执行性**：参数绑定和短时段查询已验证，资源超限明确停止；其他时段覆盖、实际性能与未来分页稳定性仍需独立核对，不能扩大当前限额直接扫描。
- **坐标语义**：WGS84 与地图展示坐标转换、局部平面适用范围、原安装参数来源；用已知方向/距离样例验证三角函数符号及单位。
- **交互行为**：调整安装点和朝向时当前点、历史尾迹及暂停画面同步更新；粗调后关联检查、逐项剔除、排除区和检查失效可区分，原参数/候选、版本与生效时间明确，原始观测保持完整。
- **算法正确性**：用已知参数的数据检查局部与跨北向恢复、初值同样本比较、筛选先于采样、连续运动门限、竞争与人工选择、训练验证隔离、重启与导出，以及旧模式全角度兼容；再用真实独立时段验证同船多点、尺寸缺失、断报、杂波、多解及低支持场景。
- **性能与接受标准**：在实际数据量下测查询、解析、重算和拟合耗时，确定取消/超时及界面反馈；未测量前不承诺响应时长或定位精度。

本工具已提供可运行实现、合成数据/接口回归和现场只读短查询验证，范围见 README；未进行浏览器调试、真实查询性能或真实场景精度验收。

## 9. 方法依据与适用边界

- [Myronenko、Song：Point Set Registration: Coherent Point Drift，2010](https://research.nvidia.com/publication/2010-12_point-set-registration-coherent-point-drift)：概率点集配准、离群点和 EM 的基础依据；不能据此认为本工具的扩展船体模型已实现或已验证。
- [Granstrom、Baum、Reuter：Extended Object Tracking: Introduction, Overview, and Applications，2017](https://isif.org/media/extended-object-tracking-introduction-overview-and-applications)：扩展目标建模和关联问题的综述，支持将船舶视为有空间范围的目标；不直接提供本项目安装参数求解器。
- [Mange 等：EUSIPCO 2024 AIS/雷达 CPD 关联研究](https://eurasip.org/Proceedings/Eusipco/Eusipco2024/pdfs/0001217.pdf)：联合关联和雷达角偏差估计的参考；其主要模型针对角度偏差，实验雷达由 AIS 轨迹模拟，不能证明未知安装位置加朝向、真实船体多点场景的性能。文中的一对一后处理不用于本工具原始点层。
- [ITU-R M.1371-6：Technical characteristics for VHF automatic identification system using time division multiple access in the maritime mobile service，2026-02](https://www.itu.int/rec/R-REC-M.1371)：AIS 字段、船体参考点、尺寸与有效值语义的官方规范入口；本项目旧解析库的兼容性需另行核对，本文不要求升级它。
- [ClickHouse 查询参数官方文档](https://clickhouse.com/docs/reference/syntax#defining-and-using-query-parameters)与 [PROJ 局部坐标转换官方文档](https://proj.org/en/stable/operations/conversions/topocentric.html)：分别用于查询参数和固定局部坐标实现；现场服务器兼容性与实际空间精度仍须验证。
