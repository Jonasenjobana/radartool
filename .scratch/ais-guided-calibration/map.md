# AIS 引导筛选与自动精调

Labels: wayfinder:map
Status: resolved

## Destination

实现[自动精调规格](spec.md)：以人工粗调为起点，先选定区域内的 AIS 船舶及其附近雷达轨迹，经过人工关联检查后，再估计局部安装参数修正。
完成标准是关联筛选、审核、求解与任务恢复可用，必要验证通过，并完成标准与规格两个轴的审查。

## Notes

- 用户已调用 implement-spec，本轮按[规格](spec.md)和任务依赖进入实施；任务按[本地 Markdown 约定](../../docs/agents/issue-tracker.md)管理。
- 用户已选择“人工粗调后自动精调”和“先检查关联，再开始标定”。此前要求的框内雷达排除仍属于输入筛选需求，其与自动筛选的结合方式由关联检查议题决定。
- 用户反馈当前自动标定效果不如人工调整。这是现场反馈，尚未通过同一数据和独立时段的量化对比确认具体根因。
- 当前[共享筛选器](../../shared/refinement.js)先依据人工粗调和真实 AIS 状态筛选连续关联，再由[模型](../../shared/model.js)均衡采样；训练关联与稳定性不借验证时段决定。
- 当前[任务提交](../../client/useWorkbench.ts)冻结人工初值与检查后的关联；[精调求解](../../server/fitter.js)只搜索局部位置和周期角。旧 refinement:null 任务仍保留完整角度搜索。50,000 限制计算位置与角度网格组合，不是雷达点数。
- 工程门限可调整；公共边界回归和构建不构成真实现场精度证明。
- 原始观测继续保留；筛选结果作为固定任务输入并记录排除依据。未关联雷达可能来自无 AIS 船舶，不能仅凭未关联认定为物理噪声。
- 遵守项目规则：简体中文、最小完整改动、沿用 Node 22.22.3 和 npm、不进行浏览器调试。术语见[领域术语](../../GLOSSARY.md)。
