# 匹配组完整时段加载与本地回放

本规格定义匹配组的完整加载、本地回放、后台标定和旧分窗历史兼容行为。

## 用户流程

1. 选择匹配组、当前雷达、完整时间范围和可选 AIS 查询矩形。
2. 点击“加载匹配组”，后台一次读取所选时段，前端显示准备阶段并允许取消。
3. 全部成员成功后统一发布完整会话，前端取得完整业务观测并保留有效的雷达选择。
4. 播放、暂停、倍速、拖动跳转、逐帧、插值、尾迹和目标跟踪使用已加载数据。
5. 自动标定引用当前雷达完整快照提交后台任务，保存、导出和归档复用完整输入。

## 加载与查询契约

- 普通加载使用 `POST /api/groups/:id/query?async=1`，提交 `start`、`end`、匹配组修订、可选 `queryArea` 和 `forceReload`。
- 202 返回准备编号，前端通过准备状态和结果接口取得完整回放 v2；加载前只恢复本地目录及查询条件。
- 时间使用真实 UTC 毫秒与 `[start, end)` 半开区间，时间轴保留首尾无数据区间。
- 一个匹配组属于同一项目，包含 1—8 台雷达和 1—100 个 AIS 来源。选择当前雷达决定参数调整与标定对象，完整查询读取全组成员。
- 雷达逐台串行读取，保留原始极坐标；原始 AIS 在组内共用，结构化 HTTP 来源保留各雷达上下文。
- AIS 查询矩形只筛 AIS 位置，包含矩形边界；安装位置搜索区和拟合 AIS 区域保持独立。
- 同组全部成员成功后一起发布；读取、解析、校验或保存失败均明确报错，不能发布半份数据或把失败标为空结果。
- 重新加载时暂停旧回放并保留旧画面和参数，失败或取消不替换原数据；成功后切换到新完整会话。
- “重新读取远程数据”强制完整回源并建立新会话，原历史保留。

## 本地回放与显示

- 播放、跳转、逐帧和尾迹调整不发起新的轨迹请求。
- 进度条拖动时只预览目标时间并暂停画面推进，松开后本地跳转，保留用户最近的播放或暂停意图。
- 上一帧和下一帧使用组内雷达、AIS 动态及既有静态报告的去重真实时刻，到达边界后停止；键盘和输入焦点保护沿用当前规则。
- 目标展示使用同一固定 ENU 平面的相邻真实位置进行线性插值，两点间隔不限；首个位置之前不显示，末点之后沿用各类目标的保留规则。
- 原始位置、极坐标、观测时间、方向及尺寸证据不因显示插值或参数调整而改写。
- 参数草稿、安装搜索区、拟合 ROI、版本选择和任务结果按雷达维护；切换当前雷达保留其草稿。
- 时间生效版本按回放时刻选择；地图跟踪及关联线使用当前展示位置。
- 当前目标和尾迹继续沿用已有显示配额，这些配额不裁剪完整快照或标定输入。

## AIS 尺寸

- 原始 AIS 动态轨迹仅选择消息 1、2、3、18，普通加载不读取静态尺寸或复用旧历史尺寸缓存。
- 点击船舶固定当时的回放时间 `positionTime`，按当前来源和 MMSI 查询后续 48 小时，返回第一份有效 5、19 或 24B 尺寸。
- 点击尺寸作为同会话的显示覆盖，播放、回退及切换当前雷达时保留；更换会话或快照时清空。
- 点击尺寸不进入原始快照、SQLite 或标定输入。旧输入已有尺寸继续按其报告时刻参与历史回放。
- 详细时间边界、分页和分片契约见 [AIS 点击尺寸补查规格](../ais-click-dimensions/spec.md)。

## 后台标定与持久化

- 标定通过 `{snapshotId, options}` 提交，服务器保存固定雷达、时段、区域、算法设置与输入摘要，立即返回任务编号。
- 后台复用已加载原始完整输入计算，前端只查询进度；切换、释放或关闭回放不取消计算。
- 任务可取消并保留失败原因，服务重启将未完成任务标记中断；项目、单位和时间对齐核实要求保持有效。
- 拟合与验证使用原有采样及证据规则，点击显示覆盖与地图配额不作为标定输入。
- 点击候选行或“对比”，以当前手调草稿为参照展示经纬度、朝向及候选减当前差值，保留草稿和设置；朝向差取最短有符号角差，位置差采用固定 ENU 平面的位移与距离。
- 地图定位当前和候选两个安装点，用不同颜色显示位置、朝向箭头、位移连线与差值标注，重合安装点仍可区分；手调时同步更新，切换候选才重新定位。“结束对比”保留草稿，“使用候选”载入候选参数和原任务设置，保存版本仍需单独操作。
- 候选对比仅用于当前完整输入；切换雷达或更换输入后清除，任务及原始观测不因预览或应用而改写。
- SQLite 保存结构化目录、成员、参数、结果摘要和业务指纹；动态轨迹和原文保留在当前工作集。
- 完整工作集在更换、释放或重启后需要按固定历史条件回源或从归档恢复。离线复现由用户明确导出或归档完成。

## 旧历史与接口兼容

- 旧分窗目录保存原成员、修订、名称、参考参数、时段、查询区域和数据契约。
- 前端打开旧分窗历史时，使用 `/api/playbacks/:id/prepare?async=1` 完整准备全组，再读取生成的完整会话；原目录保留。
- 旧完整会话、单雷达快照和 gzip 归档保留原有恢复方式。重新读取历史数据建立新 ID，并明确业务指纹是否变化。
- 后端分窗、相邻报告、缓存和取消接口保留已有调用方兼容，既有后台 `{playbackId, radarId, options}` 提交仍由服务器准备完整输入后计算。
- 原始详情与任务证据继续绑定其真实快照或来源观测；不按别的范围的行号返回原文。
- 本次不删除、搬迁、压缩或重写旧数据库正文和归档。

## 验收

- 使用真实 Fastify 接口、受控数据源及 Node 中运行的 Vue 工作台状态，不进行浏览器调试。
- 核对完整查询的时段、成员、区域和修订，发布后包含所选范围的全部业务观测。
- 核对加载前雷达选择、加载后选择保持、逐台参数草稿和历史版本。
- 加载后播放、拖动、逐帧和尾迹调整均不请求远程轨迹；长间隔插值、方向、尺寸与原始数据保持现有语义。
- 阻塞完整读取，验证准备状态、取消、旧画面保留和迟到结果隔离；注入失败后可重新完整加载。
- 核对旧分窗历史完整恢复、原目录保留、完整快照任务打开和候选对比；预览不改草稿，应用不改任务，跨北向角差、重合安装点与切换雷达的清理正确。
- 核对标定复用已加载输入，释放页面后任务仍可结束，提交后修改设置不改变任务条件。
- 旧服务端窗口接口继续验证身份、相邻报告、多片完整性、缓存预算、取消和原子发布。
- 类型检查、构建和接口验收不等于浏览器、现场资源或标定精度验收；真实完整查询耗时与浏览器内存仍需实际环境验证。
